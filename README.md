# CORE-BUSY 核忙

> 看看你的 CPU：谁在爆肝，谁在摸鱼，谁在偷偷升级。

Windows 下的**逐核 CPU 养成游戏**：背景是一块 PCB 主板，每颗物理核是焊在上面的一颗芯片。
负载就是喂食 —— 核越忙经验越多，攒够了就升级、进化；打开软件看一眼谁在爆肝、谁在摸鱼、
谁的等级条又长了一截。

![CORE-BUSY 主界面](docs/screenshot-dashboard.png)

## 玩法与功能

| 功能 | 说明 |
| --- | --- |
| 芯片角色卡 | 一颗物理核 = 一张芯片卡：金色引脚封装 + Die 区等级大字 + 成长阶段（幼体 → 成长期 → 成熟期 → 究极期 → 满级传说）+ 性格角色 + EXP 进度条 |
| 喂食 = 负载 | 核越忙经验涨得越快；占用率、频率、SMT 线程明细都在卡的下半部。可切换**实时 / 累积**两种口径 |
| 经验动画 | 点击芯片弹出的角色卡里，EXP 条**平滑生长**（每次采样补间），右下角直接给出「**距升级约 X**」的 ETA 预估 |
| 性格角色 | 六种：摸鱼 / 闲时热手 / 稳态 / 苦劳 / 尖峰 / 夜猫 —— 由负载形状与昼夜分布判定，先形状后水平 |
| 等级跨进程延续 | 经验账本落盘 `%APPDATA%`，关掉重开进度还在；等级只表示「这颗核陪你跑了多久」 |
| 状态栏 | 显卡 / 内存 / 硬盘（大小 · 占用 · 温度）│ **累计运行时间**（悬浮看本次 / 上次）│ **累计整机能耗**（悬浮看本次 / 口径声明） |
| PCB 主板皮肤 | 板基 / 铜走线 / 焊盘 / 安装孔 / 丝印全部矢量静态绘制，零每帧渲染开销；高负载时芯片边框红色强调 |
| 托盘与省电 | 托盘常驻；性能模式（采样降为 2000ms 并暂停传感器轮询）；主题跟随 CPU 厂商（角标颜色随之联动） |
| 开机启动 | 设置中一键开关（当前用户注册表 Run 项，无需管理员权限） |

## 下载与运行

从 [Releases](https://github.com/FiveDayZ/core-busy/releases) 下载 `CoreBusy-v{版本}-win-x64.zip`，
解压后双击 `CoreBusy.App.exe` 即可 —— **单文件自包含**，无需安装 .NET 运行时。

> **权限**：以管理员身份运行才能读温度 / 功耗 / 风扇（需 Ring0 驱动）。
> 非管理员时功耗与风扇显示 `-`；读数一律**不拿 0 冒充**：读不到就是 `-`。

从源码构建（本机无系统 .NET，脚本会把 SDK 解压到用户目录，不做全局安装）：

```bash
python scripts/setup-dotnet-sdk.py     # 恢复 .NET SDK 8.0.425
python scripts/build-release.py        # Release 构建 → 单文件发布 → 打包
python scripts/lint_ui.py              # XAML 结构 + 绑定完整性静态检查
```

## 成长体系：经验 / 等级 / 角色

**经验口径：满负荷核·时**（实测占用率的时间积分）：

- 占用 ≥ 15% 按负荷计（1:1 积分）；
- 占用 5%~15% 由陪伴兜底（×0.15，"在岗就算干活"）；
- 占用 < 5% 完全摸鱼，不给经验。

等级 1–99，经验要求由解析式曲线生成（累计值相对容差 1e-15，跨版本稳定）。
每张芯片卡顶部的 EXP 条是**平滑动画**：经验每 0.8 秒累积一次，条宽随之补间生长；
角色卡里的 ETA 按本次运行的经验速率外推升级时间，满级 / 速率未知 / 遥遥无期各有直白文案。

性格角色与等级并列：等级是"跑了多久"，角色是"怎么跑的"（负载形状特征先于水平特征判定，
例如长期夜段活跃的核会被认成「夜猫」）。两者都持久化到磁盘，重装不丢。

## 状态栏

左列：**显卡 → 内存 → 硬盘**（大小 · 占用 · 温度，读不到的项自动隐藏）。
右列：**累计运行时间**（悬浮：本次 / 上次）│ **累计整机能耗**（悬浮：本次 / 累计 / 口径声明）。

整机能耗是**估算，不是实测**——本机没有整机功率来源，原则是"能测就测，测不到按型号估"：
CPU 封装功耗实测；显卡有传感器用实测、否则按型号额定 × 负载（核显已含在封装内不重复计）；
内存按容量 × 代际系数；硬盘逐盘空闲 + 活动度摆幅；风扇按转动个数；主板固定开销。
数值自带 `≈` 前缀，传感器中断时冻结转弱色（**绝不拿 0 冒充**）。
系数可在 `%APPDATA%\CORE-BUSY\settings.json` 校准，无需重新编译。

## 核心负载口径：实时 / 累积

分区标题右侧可切换，同一张芯片卡、同一套色阶，只换读数含义：
**实时** = 瞬时使用率 + 频率；**累积** = 运行期时间加权均值 + 等效满负荷量 + 名次。
积分始终在跑（与视图无关），Δt 一律取墙钟差；「重置」可清零累积统计。
状态分档：0–5 摸鱼 / 5–20 空闲 / 20–50 工作 / 50–80 忙碌 / 80–95 高负载 / 95–100 爆肝。

## 主题

| 主题 | 触发 | 说明 |
| --- | --- | --- |
| Intel Blue | CPU 为 Intel，或手动锁定 | 深蓝基底，蓝色强调 |
| AMD Red | CPU 为 AMD，或手动锁定 | 近黑基底，红色强调 |
| Neutral | 厂商未知 | 中性石墨基底，低饱和蓝强调 |

三套主题共用同一中性深灰基底，唯一差异是强调色；标题栏与状态栏的品牌角标
（「Die 2×2 负载格」）随主题联动换色。高负载（≥ 80%）统一红色强调。改动主题需重启。

## 设置

| 段 | 内容 |
| --- | --- |
| 采样周期 | 500 / 1000 / 2000ms，**立即生效**并持久化 |
| 硬件传感器 / 游戏模式 | 传感器开关（关闭更省电）；游戏模式全屏检测联动 |
| 关闭行为 | 关闭窗口时最小化到托盘（托盘双击恢复 / 右键退出） |
| **开机自动启动** | HKCU 注册表 Run 项；注册表为唯一事实来源，任务管理器里手动禁用后设置页如实回显 |
| 主题 / 核心分区 | 自动 / Intel / AMD（需重启） |
| 电源策略 / 进程规则 | 读取并切换电源方案；一键降级后台负载，游戏模式联动 |

## 数据文件

数据在 `%APPDATA%\CORE-BUSY\`（标题栏「更多」按钮可直接打开）：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 用户配置 |
| `core-exp.json` | 逐核经验账本（等级跨进程延续的数据源；口径不符自动归档重建） |
| `core-roles.json` | 逐核性格角色账本（按 max 合并，峰值 NaN 不参与比较） |
| `runtime.json` | 累计运行秒数 + 上次会话时长 |
| `energy-history.json` | 每日整机估算能耗与观测秒数（累计功耗与历史账本的数据源，带口径标识） |
| `core-health.json` / `core-voltage.json` | 历史最好站位 / 逐核电压采样 |

## 环境变量

无 UI 入口，发布版同样可用：

| 变量 | 取值 |
| --- | --- |
| `COREBUSY_MOCK_CPU` | `intel-hybrid`（默认）/ `intel-standard` / `amd-single` / `amd-dual` |
| `COREBUSY_FORCE_BRAND` | `intel` / `amd` / `neutral` |
| `COREBUSY_CORE_VIEW` | `cumulative` —— 直接以累积视图启动 |
| `COREBUSY_SOFTWARE_RENDER` | `0` 试硬件加速 / `1` 显式锁软件渲染；不设 = 软件渲染 |
| `COREBUSY_DATA_DIR` | 重定向数据目录（不含 `settings.json`，它固定读 `%APPDATA%`） |

## 项目结构

```text
src/
├── CoreBusy.App      # WPF 主程序（UI / ViewModel / 养成体系服务 / 托盘 / 主题）
├── CoreBusy.Core     # 领域模型（Progression：经验曲线 / 累加器 / 角色分类器）
├── CoreBusy.Windows  # 真实采集（CPU 拓扑 / 性能计数器 / WMI / 电源策略）
└── CoreBusy.Sensor   # 硬件传感器（LibreHardwareMonitor）
scripts/              # 构建与静态检查脚本
docs/                 # 设计文档与各版本截图（EXP 曲线推导见 docs/EXP-DESIGN.md）
```

`ICpuMonitorService` 是 UI 与硬件采集的唯一边界：`WindowsCpuMonitorService` 为默认注入，
`MockCpuMonitorService` 作为回退，UI 无感知。

## 构建与发布

| 脚本 | 作用 |
| --- | --- |
| `setup-dotnet-sdk.py` | 按约定版本（8.0.425）下载并解压 SDK 到 `~/.workbuddy/binaries/dotnet-sdk`；已存在则跳过 |
| `build-release.py` | `dotnet build` → `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` → `dist/CoreBusy.App.exe` → 打包 zip。`--variant full\|lite\|both`，`--no-publish` 只编译 |
| `lint_ui.py` | 校验全部 `.xaml` 的 XML 结构，并把每个 `{Binding X}` 与 C# 公开成员比对 —— WPF 对拼错的绑定路径只写 trace、界面静默空白，此检查用于提前拦截 |

发布产物（`dist/`）：

| 文件 | 说明 |
| --- | --- |
| `CoreBusy.App.exe` | 单文件自包含，约 159 MB。本机无系统 .NET 8 运行时，故必须 self-contained |
| `CoreBusy-v{版本}-win-x64.zip` | 分发用压缩包 |
| `CoreBusy-v{版本}-win-x64-lite.zip` | 精简版通道，exe 约 4.9 MB，需系统安装 .NET 8 桌面运行时 |

> 单文件**不压缩**：压缩会把全部托管程序集在启动时解压进内存，实测用约 85 MB 工作集
> 换 89 MB 体积。对常驻托盘的小工具，运行内存比下载体积要紧。
> 版本号取自 `src/CoreBusy.App/CoreBusy.App.csproj` 的 `<Version>`，并同步显示在状态栏。
